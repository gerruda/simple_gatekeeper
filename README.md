# Бот-привратник для Telegram

Телеграм-бот, который встречает новых участников группы, показывает правила
и снимает ограничения после нажатия инлайн-кнопки «Принимаю».

> Проект разработан вручную, без инструментов генерации кода на базе ИИ.
> Цель — показать владение синтаксисом Go, стандартной библиотекой и
> архитектурным подходом «порты и адаптеры».

## AI FREE

Так как проект больше учебный пет проект для собеседований, он создавался без испрользования AI. Исопльзвоаласть только справочная информация по используемым библиотекам. Другие проекты, с использвоанием AI  инстурментов, можно найти в других моих репозиториях.

## О проекте

В Telegram есть «заявки на вступление в группы», но их
можно обходить. Бот-привратник решает задачу иначе: новый участник
попадает в группу, но не может писать, пока не примет правила.
Правила приходят вместе с инлайн-кнопкой, а после нажатия ограничение
снимается. Самописные боты на клиентах телеграм, не умеют нажимать на inline кнопки или не ожидают их.

Ограничение: невнимательные пользователи тоже могут «застрять» без прав,
поэтому в текст правил стоит добавлять контакт администратора. Это уже
задача персонализации бота под конкретную группу и в текущую версию
не входит.

## Возможности

- приветствие новых участников группы;
- ограничение прав до принятия правил;
- инлайн-кнопка, привязанная к конкретному пользователю;
- проверка, что кнопку нажал именно адресат;
- идемпотентная обработка повторных нажатий;
- временное хранение ожидающих в памяти (интерфейс позволяет заменить
  реализацию на Redis или БД);
- команды `/start` и `/help`.

## Как это работает

1. Бот добавлен в группу и назначен администратором.
2. Приходит обновление `NewChatMembers`.
3. Роутер определяет тип обновления и передаёт событие в сервис `welcome`.
4. Сервис проверяет, не админ ли пользователь и не ждёт ли он уже ответа,
   добавляет его в список ожидающих, ограничивает права и отправляет
   правила с кнопкой. В callback data записывается `Accept:<userID>`.
5. Пользователь нажимает кнопку — приходит `CallbackQuery`.
6. Роутер разбирает callback data и передаёт в сервис два идентификатора:
   кто нажал (`actorID`) и кому предназначена кнопка (`targetID`).
7. Сервис проверяет, что `actorID == targetID`, снимает ограничение
   и удаляет запись из памяти.
8. Адаптер отвечает Telegram на callback и удаляет сообщение с правилами.

## Архитектура

Проект построен по схеме «порты и адаптеры» (гексагональная архитектура).

- `ports` — интерфейсы исходящих зависимостей: отправка сообщений,
  ограничение участников, проверка администратора, хранение ожидающих.
- `services/welcome` — сценарий приветствия и принятия правил.
- `adapters/telegram` — клиент Bot API (реализует порты) и роутер
  (входящий адаптер: update → вызов сервиса).
- `adapters/memory` — реализация хранения ожидающих на map в памяти.
- `config`, `logger` — инфраструктура.
- `cmd/main.go` — собираем граф зависимостей.

Почему так: бизнес-логика не зависит от Telegram и тестируется без сети;
адаптер памяти заменяется на Redis без изменений в сервисе; новый
транспорт (CLI, HTTP) добавляется отдельным адаптером.

### Принятые решения

- **В callback data хранится `userID`, а не состояние.** Данные живут
  в сообщении и переживают перезапуск бота; память нужна только чтобы
  не приветствовать пользователя дважды.
- **Сервис не ждёт нажатия кнопки.** Он завершает работу, а ответ
  приходит отдельным событием. Это делает сценарий неблокирующим.
- **Проверка «кто нажал» — в сервисе.** Это бизнес-правило, а не
  особенность Telegram, поэтому оно тестируется без адаптера.

## Структура проекта

```text
.
├── cmd/main.go                 # composition root
├── internal/
│   ├── adapters/
│   │   ├── memory/             # хранение ожидающих в памяти
│   │   └── telegram/           # Bot API client + router
│   ├── config/                 # viper + godotenv
│   ├── logger/                 # zap
│   ├── ports/                  # интерфейсы (исходящие порты)
│   └── services/welcome/       # сценарий приветствия
├── config.yaml                 # локальная конфигурация (не коммитится)
├── .env                        # BOT_TOKEN (не коммитится)
└── go.mod
```

## Требования

- Go — версия не ниже указанной в `go.mod`;
- бот, созданный в [@BotFather](https://t.me/BotFather);
- права администратора в группе: ограничение участников;

## Конфигурация

Скопируйте пример и укажите токен:

```bash
cp config_example.yaml config.yaml
```

Токен также можно задать в `.env` как `BOT_TOKEN=...` — эта переменная
имеет приоритет над `config.yaml`. Оба файла не коммитятся.
